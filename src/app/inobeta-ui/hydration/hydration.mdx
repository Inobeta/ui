# Hydration

Use the `ibSetupHydration` function to set up persisted NgRx state. Provide a unique storage key and
the names of stores present in your app that you want to save in browser storage.

For the stores used by the current application configuration, the persisted keys can include:
- `ibHttpSessionState`: holds user authentication data
- `ibKaiTable`: current Kai Table state feature, registered by `IbKaiTableModule`

```typescript
import { ApplicationConfig } from "@angular/core";
import { provideEffects } from "@ngrx/effects";
import { provideState, provideStore } from "@ngrx/store";
import {
  ibHttpEffects,
  ibLoaderFeature,
  ibSessionFeature,
  ibSetupHydration,
} from "@inobeta/ui";

const appStorage = ibSetupHydration("app-storage", [
  "ibHttpSessionState",
  "ibKaiTable",
]);

export const appConfig: ApplicationConfig = {
  providers: [
    provideStore(undefined, { metaReducers: appStorage.metareducers }),
    provideState(ibSessionFeature),
    provideState(ibLoaderFeature),
    provideEffects(ibHttpEffects),
    provideEffects(appStorage.effects),
  ],
};
```

Table Views are not hydrated through NgRx. `IbViewStorageService` persists each table's Views in `localStorage`, using a per-table key derived from its configured prefix and group name.
