# What's new

## Version 20.0.0

Version 20 updates the library for **Angular 20** and introduces a refactored Kai
Table architecture. The package does not enforce a specific Node.js version; use
a version supported by your Angular 20 toolchain.

## Release highlights

- **DEVK-693 — Angular 20 compatibility:** the library is compatible with Angular
  20.
- **DEVK-912 — Decoupled Kai Table views:** Kai Table no longer requires the
  Views implementation. Views are optional and can be restored by importing the
  separate Views module and adding a views host.
- **DEVK-1066 — Kai Table refactor:** table state, signal APIs, and local and
  remote data-source contracts were redesigned. See the [Kai Table
  documentation](./app/inobeta-ui/ui/kai-table/table.mdx) and [migration
  guide](./app/inobeta-ui/ui/kai-table/deprecation-guide.md).
- **DEVK-1065 — Optional table Views:** user-defined views support is available
  through the optional Views integration, including saving and restoring table
  state.
- **DEVK-1046 — Table height:** desktop Kai Table supports `tableHeight`, with
  exact CSS heights or parent-filling layout.

## Kai Table migration

The following Kai Table changes require consumer updates:

- Add the required, unique `tableName` to every table.
- Read signal-based inputs and queries programmatically by calling them, for
  example `table.tableName()` and `table.sort()`.
- Do not migrate to a generic table-level row-click output: it is not part of
  the API. Use `IbSelectionColumn.ibRowSelectionChange` for row selection.
- Bind either `[data]` or `[dataSource]`; they are mutually exclusive.
- `tableHeight` now defaults to `"parent"`. Set an explicit CSS height when
  preserving fixed content sizing, and remove obsolete height overrides.

See the [Kai Table migration guide](./app/inobeta-ui/ui/kai-table/deprecation-guide.md)
for detailed input, output, data-source, and state migration guidance.

## Deprecations

Main Menu and Breadcrumbs are deprecated in v20 and planned for removal in v21.
